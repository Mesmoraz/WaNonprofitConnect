Lifecycles

stateDiagram-v2
    direction LR
    state "Org claim" as Claim {
        [*] --> Pending
        Pending --> Verified : auto (email domain) or admin approves
        Pending --> Rejected : admin rejects
        Verified --> Revoked : member removed / abuse
    }
    state "Listing" as L {
        [*] --> Open
        Open --> Matched : match accepted
        Matched --> Fulfilled : match completed
        Matched --> Open : match cancelled
        Open --> Closed : owner closes
        Open --> Expired : past expiry
    }
    state "Match" as Mt {
        [*] --> Proposed
        Proposed --> Accepted : other side accepts
        Proposed --> Declined : other side declines
        Accepted --> Completed : either side
        Accepted --> Cancelled : either side
        Proposed --> Cancelled : proposer withdraws
    }

What each table holds

TableKey fieldsNotes
ORGANIZATIONein PK, name, city, zip, ntee_code, foundation_code, is_501c3, is_activeFrom the IRS BMF (exists). is_active = in Pub 78 and not on the revocation list (2b).
ORG_PROFILEein FK, mission, website, public_contact, logo_urlEditable by members; IRS block stays read-only beside it.
TAG / ORG_TAGname, kind (need · have · cause) / ein, tag_id, kindShared vocabulary so "laptops" means the same everywhere. Drives alerts with no listing posted.
USERid, email, display_name, auth_provider (google · email), account_types, created_atASP.NET Identity. Account types are a set, not one value.
ORG_CLAIMuser_id, ein, method (email_domain · mailed_code · document · member_invite · admin), status (pending · verified · rejected · revoked), evidence_ref, reviewed_byPluggable verification. Evidence is a reference to a file or secret, never inline PII.
ORG_MEMBERuser_id, ein, role (owner · editor · viewer)Created when a claim is verified or an invite is accepted.
BUSINESS / BUSINESS_MEMBERname, ubi, domain, status / user_id, business_id, roleUBI = WA business license id, looked up at verification.
SUBSCRIPTIONowner_type (business · user), tier (local · regional · pwyw), amount, stripe_id, status, renews_atStripe Billing. Nonprofits never have one.
DONATION_PROOFuser_id, ein (recipient), donated_on, evidence_ref, statusThe supporter join gate; evidence of a gift made elsewhere, not through us.
LISTINGkind (need · offer), owner_type (org · business), owner_id, category, title, quantity, urgency, status, tags, expires_atExists; gains owner_type.
MATCHneed_listing_id, offer_listing_id, proposed_by, status, scoreExists, unchanged.
MESSAGEmatch_id (or collaborate_thread_id), sender_user_id, body, sent_atExists; sender becomes a user, threads can exist without a match (2e).
ALERT_RULEowner_type (org · user), owner_id, categories, keywords, radius_miles, channels (inapp · email · push), digestDefault rule generated from tags + category + area; editable.
NOTIFICATIONuser_id, type (match_found · match_proposed · message · claim_verified …), payload_json, read_atIn-app record; email/push are deliveries of the same row.
PLACEMENTbusiness_id, type (sponsored_offer · need_sponsorship · category_sponsor · directory_card), target, status (pending · approved · live · ended · rejected), starts_on, ends_onAllow-listed types only; admin-reviewed; always labeled "Sponsored".
FOLLOWuser_id, einSupporters (and anyone) following an org.
REPORTreporter_id, target_type, target_id, reason, statusModeration queue input.
